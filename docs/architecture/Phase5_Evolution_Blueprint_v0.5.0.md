## 0. 战略北极星

**目标升级为：全天候的个人与团队数字员工，越用越懂你。**

语义要点（对产品与架构的含义，而非当期实现承诺）：

- **全天候**：离线/降级可用性、会话与任务的可持续承接、团队在时间与角色上的接续（ownership、交接、可追溯）。
- **数字员工**：可委派、可复述目标、可多步执行与复盘，但必须保留 **可归因、可审计、可撤回** 的护栏（与现行 `MetaFramework` / 证据边界一致或显式演进）。
- **越用越懂你**：长期偏好与工作语境建模须与 **`mrag_core` 索引语料、`hermes_engine` 会话边界**明确分离治理；仅能经 **明示同意、可审查、可导出/可删除** 的管线进入「懂你」一侧（具体形态在 Phase 5 分叉评估中选型）。

## 1. 首期工程边界（止于 Phase 4 收官）

本项目 **首期工程（Program tranche one）** 的交付收口与 **Phase 1（工程预览期）路线图**（`Phase1_Roadmap_v0.2.0.md`）是两件事：

| 称谓 | 含义 |
|------|------|
| **Phase 1（历史文档）** | 已结束的 **engineering preview** 范围（侧契约、MRAG 守界、Skill 不显式脚本执行等）。 |
| **首期工程（本蓝图用语）** | 从 Phase 2 可用工作台贯穿 **Phase 3→Phase 4 产品化收口** —— 即到 `Phase3_Phase4_Productization_Roadmap` §2 中 **Phase 4 退出条件** 可被诚实声明为满足（含清单 `Phase3_Phase4_Exit_Checklist_v0.3.0.md`）。 |

**结论：** Phase 5 所载能力 **不属于** 首期收口承诺项；不得在 Phase 4 未收官前混入「必须用 Phase 5 才能讲圆」的退出依赖。

## 2. 为何 Phase 5 是「路线分叉」而非功能迭代

实现北极星所依赖的能力（持续学习、团队画像、强个人化、可能的多租户与联邦）会触及：

- **推理与工具编排入口**（继续产品自有 `hermes_engine` vs 更多依赖上游/外部 Agent 运行时）；
- **LLM 接入层**（继续维护并收敛 `llm_gateway` vs **直接采用或深度集成上游统一网关** —— 含协议、计费、路由、遥测、合规边界）；
- **记忆与知识的法域**（会话态、工作记忆、用户/团队模型 vs `mrag_core` 只读知识库）；
- **发布形态**（单列大版本：一次定义「数字员工」合约，而非长期打补丁式小功能）。

因此 Phase 5 应作为 **单独规划纵列**，在 Phase 4 收口后启动 **架构与商业—技术前提** 的对比评估，再立项实现；**不可**简单折叠为「Phase 3F 再加几条启发式」。

## 3. 分叉主线（必须在 Phase 5 立项前完成纸面/ PoC 结论）

以下两条 **至少** 要做成可比的决策包（范围、成本、风险、回归策略、与现有契约 `sidecar_api` / 桌面的关系）：

### 3.1 路线 A — 继续以 PycHermes 为主干深化

- 强化 `llm_gateway`：多提供商、团队密钥策略、用量与稽核挂钩（若需要）。
- 明确 **记忆与偏好** 的存储边界（禁止污染 `mrag_core` 知识库职责）。
- 定义「越用越懂你」的 **可撤回数据模型** 与导出/删除义务。

### 3.2 路线 B — 直接采用 / 深度集成上游网关（或指定外部 Agent 平台）

- 将 `llm_gateway` 部分或全部替换为上游实现；**禁止** 让上游 SDK 对象越过既定边界泄漏进 `hermes_engine` / `meta_harness`（或接受一次 **有意识的** 边界重划并更新 ADR）。
- 评估与 **本地侧车、桌面、formal 分析路径** 的耦合成本；尤其 `MetaFramework.execute()` 是否仍为正式分析唯一入口。

### 3.3 决策产物

- 一份 **ADR：Phase 5 运行时与网关选型**（A / B / 混合：如网关上游 + 本地 MRAG 不变）。
- 一份 **大版本迁移说明**（契约版本、桌面 IPC、索引格式若变更）。

## 4. Phase 5 能力纵列（方向性，非首期任务）

下列主题只在 Phase 5 规划；**不**作为 Phase 4 退出门槛：

| 纵列 | 说明 |
|------|------|
| **个人与团队模型** | 偏好、节奏、领域词表、项目语境；与 MRAG 语料分账。 |
| **委派与交接** | 任务粒度的可传递状态、责任人与审计。 |
| **可靠性 SLO** | 「全天候」下的错误预算、降级叙事与自动恢复（与现有 degraded 体验衔接）。 |
| **协作与治理** | 规则/技能发布审签、团队级策略与合规（与 Track D 衔接但规模升级）。 |
| **评测** | 数字员工场景集（非仅检索 hybrid top-1）；人机协同指标。 |

## 5. 版本与发布节奏

- Phase 5 对应 **单列大版本线**（例如产品对外宣称为一次代际升级），与 Phase 3→4 的连续小版本习惯解耦。
- 契约与安装路径变更须同步 **`Compatibility_Matrix.md`** 与发布治理文档。
