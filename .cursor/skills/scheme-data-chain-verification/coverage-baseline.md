# MECE 覆盖基线：报告类型维度映射与信息缺口检测

> **来源**：本技能 **MECE 维度基线**（与完备性检查/10 维清单同构）。叙事标签约定见 [methodology.md](methodology.md) · §0。

## §1 报告类型分类

| 类型 | 代码 | 典型场景 | 关键判断 |
|------|:----:|---------|---------|
| **芯片对比** | CC | 多芯片 vs 同一需求 | 选出最优芯片 |
| **选型论证** | SA | 单一需求 → 芯片+DDR+编码全链路 | Go/No-Go + 配置推荐 |
| **可行性分析** | FA | 已知芯片+DDR，验证特定场景 | 容量/编码/带宽能否达标 |
| **技术对比** | TC | 两代芯片/平台演进对比 | 差异量化 + 升级建议 |

## §2 MECE 维度基线（按报告类型）

### 2.1 芯片对比（CC）

| # | 维度 | MECE 覆盖要求 | 检查方法 |
|:--|------|-------------|---------|
| CC-1 | 基础规格 | 工艺/频率/核心数/封装 | grep 各芯片关键参数 |
| CC-2 | 编码能力 | 标称+需求 MP/s 对比表 | 公式校验：MP×fps vs 标称 |
| CC-3 | DDR 配置 | 各芯片支持的最大/常用 DDR 配置 | DDR 命名规则校验 |
| CC-4 | AI/NPU | NPU 算力 + AI-ISP 帧率 | binning-mode 机制确认 |
| CC-5 | 内存分配 | 各配置下 Media/OS 分配 | Media+OS=总容量 强制校验 |
| CC-6 | **功耗** | 各芯片典型/峰值功耗 | 需实测值，不可仅凭 datasheet |
| CC-7 | **成本/供货** | 芯片单价 + DDR 成本差异 | L4 经验数据需标注 |
| CC-8 | ISP 能力 | ISP 规格（3A/WDR/降噪等） | 产品需求匹配 |
| CC-9 | 接口/外设 | MIPI/USB/SDIO/Ethernet 等 | 确认不缺接口 |

### 2.2 选型论证（SA）

| # | 维度 | MECE 覆盖要求 | 检查方法 |
|:--|------|-------------|---------|
| SA-1 | 需求定义 | 分辨率/帧率/编码格式/路数 | 产品规格书对齐 |
| SA-2 | 候选芯片 | 至少 2 个候选 | 编码能力过滤 |
| SA-3 | 实测基准 | 已知场景的峰值占用实测数据 | 必须有出处 |
| SA-4 | **推算链** | 实测→增长因子→外推→各配置 | 加权因子展开式校验 |
| SA-5 | DDR 比较 | 多配置横向对比表 | 命名规则+容量+余量 |
| SA-6 | 编码余量 | 每个目标帧率下需求 vs 标称 | MP/s 公式校验 |
| SA-7 | **风险分析** | 推算不确定性 + binning 验证状态 | L5 边前置条件=✗ |
| SA-8 | **成本** | 芯片 + DDR + 外围差异 | 显式标注 L4 来源 |
| SA-9 | 建议行动 | 短期/中期/长期具体步骤 | 每步带验收标准 |

### 2.3 可行性分析（FA）

| # | 维度 | MECE 覆盖要求 | 检查方法 |
|:--|------|-------------|---------|
| FA-1 | 目标规格 | 分辨率/帧率/编码参数 | 与需求对齐 |
| FA-2 | 芯片编码约束 | 标称像素带宽 vs 需求 | 超出比例分级 |
| FA-3 | DDR 配置 | 目标配置的容量+Media分配 | 命名规则校验 |
| FA-4 | Media 峰值推算 | 实测基准→加权增长因子→推算 | 展开式完整验证 |
| FA-5 | Media 余量 | 分配−推算，正/负值 | 正值=可行, 负值=需降级 |
| FA-6 | OS 内存 | OS 分配+推算增长 | 独立推算，不与 Media 混 |
| FA-7 | **Go/No-Go** | 明确结论+支撑数据 | 至少 2 维度达标 |
| FA-8 | 边界条件 | 什么条件下结论会反转 | 显式写出 |

### 2.4 技术对比（TC）

| # | 维度 | MECE 覆盖要求 | 检查方法 |
|:--|------|-------------|---------|
| TC-1 | 规格对比表 | 核心参数一行对比 | 至少 10 项关键参数 |
| TC-2 | 性能差异量化 | 编码/DDR/AI 各维度百分比差异 | 公式计算+来源 |
| TC-3 | DDR 实测 | 新旧平台相同场景内存占用 | 必须有实测数据 |
| TC-4 | 功耗对比 | 新旧平台实测功耗 | 需实测值，不可仅凭 datasheet |
| TC-5 | 升级价值 | 各维度收益量化 | 编码提升/AI提升/成本变化 |
| TC-6 | 风险 | 升级兼容性+验证状态 | L5 边前置条件 |
| TC-7 | 建议 | 升级时机+前置条件 | 带时间线 |

## §3 MECE 缺口检测流程

```
1. 识别报告类型（CC/SA/FA/TC）
2. 从 §2 加载对应维度基线
3. 逐维度 grep 报告确认：
   - ✅ 有数据 → 标记为 COVERED
   - ⚠️ 有提及但缺具体数字 → COVERED-PARTIAL
   - ❌ 完全缺失 → GAP
   - ⊘ 显式声明 N/A 或待补充 → GAP-DECLARED
4. 统计缺口：
   - 未声明缺口(GAP)数 > 20% → 报告不完整（P1）
   - 关键维度(GAP) → P0
   - 声明缺口(GAP-DECLARED) → 列入风险表即可
```

### 关键维度判定

以下维度缺失任一即判定为 **P0**（不论报告类型）：
- 芯片编码能力（标称像素带宽）
- DDR 配置与容量
- Media 峰值推算（若涉及外推）
- 核心结论的支撑数据

## §4 缺口标注规范

在验证报告中使用的标注格式：

```
| 维度 | 状态 | 说明 |
|------|:----:|------|
| 功耗对比 | ❌ GAP | 报告自称对比但仅含 538A 数据，533 侧缺失 |
| 成本/供货 | ⊘ GAP-DECLARED | 报告 §8 声明「成本对比超出本报告范围」 |
| ISP 能力 | ⚠️ COVERED-PARTIAL | 有 ISP 型号但缺处理能力详细数据 |
```

## §5 SS 级评分降级路径

> **来源**：本技能 **SS 级质量降级路径**（SSS→SS→S→A），与 [SKILL.md](SKILL.md) · §3.4 同构。命名约定见 [methodology.md](methodology.md) · §0。

| 等级 | 条件 | 通过率 |
|:----:|------|:------:|
| **SSS** | 全部维度 COVERED，无 GAP，无 P0/P1 缺陷 | 100% |
| **SS** | 全部关键维度 COVERED，GAP ≤1 项（已声明），无 P0，P1 ≤2 | ≥95% |
| **S** | 关键维度 COVERED，GAP ≤3（含 ≤1 未声明），P1 ≤3 | ≥90% |
| **A** | 关键维度 1 项缺失或 P1 ≥4 | ≥80% |
| **B** | 关键维度 ≥2 缺失或存在 P0 | <80% |

> **强制降级**：存在 P0 缺陷 → 最高 B 级，必须修复后才能定稿。
