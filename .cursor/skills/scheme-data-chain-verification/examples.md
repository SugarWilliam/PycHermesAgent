# 本对话实录中的典型修正案例

> 以下所有案例均来自 `16MP单目IPC芯片与DDR选型分析报告` 的迭代修正过程。

---

## 案例1：DDR容量命名规则纠正（P1）

**错误**：报告多处将 DDR3 2+1 写成 640MB（假设3片DDR3）。

**用户纠正**：
> "DDR3 1+1 是指 1GbDDR3 + 1GbDDR3, DDR3 2+1 是指2GbDDR3 + 1GbDDR3，以此类推。你总是计算错误，要严谨"

**修正动作**：
1. 建立 DDR 命名标准表（SSOT）
2. 全报告 grep 替换所有 DDR 容量值
3. 强制校验每配置 Media+OS=总容量

**修正结果**：
| 配置 | 修正前 | 修正后 |
|------|:------:|:------:|
| DDR3 2+1 | 640MB/3片 | **384MB/2片** |
| DDR3 2+2 | 1GB/4片 | **512MB/2片** |

## 案例2：加权增长因子算术错误（P2, C2）

**错误**：加权增长因子计算时跳步心算，0.58×1.11 未正确计算为 0.6438，导致最终因子 1.15（正确为 1.22）。

**发现方式**：用户要求 `R109 全链路验证`，发现 R109 边表锚点中的 "加权增长因子1.15" 无法从展开式推导。

**修正验证**：
```
展开式验证:
0.40 × 1.39 = 0.5560  ✅
0.02 × 1.00 = 0.0200  ✅
0.58 × 1.11 = 0.6438  ← 关键，正确结果
─────────────────
总和         = 1.2198 → 1.22
```

**连锁影响**：
- Media 峰值占用：134.02 → 142.18MB（+8.16MB）
- DDR3 1+1 余量：-6.02 → -14.18MB（更严重）
- DDR3 2+1 余量：121.98 → 113.82MB（仍充裕）
- DDR4 余量：377.98 → 369.82MB（仍充裕）

**全链路修正位置**：18 处（§5.1/§5.2.4/§5.2.5/§6.2/§3/§执行摘要/附录B）

## 案例3：像素带宽数值不统一（P3, C1）

**错误**：16MP@20fps 像素带宽在报告不同位置出现 314MP/s 和 315MP/s 两种值。

**发现方式**：用户提供的 R109 边表审计标注 `C1: 16MP@20fps像素带宽314vs315不一致`。

**修正动作**：
1. 统一选择 315MP/s 作为标准值
2. 超出比例从 4.7% 统一为 5.0%
3. grep 全报告替换所有 314 → 315，4.7% → 5.0%

**修正位置**：11 处（§1/§3/§4/§5.2.2/§5.2.5/§6.2/§6.4/§执行摘要）

---

## 案例4：边表锚点与正文binning-mode矛盾（P4）

**错误**：R109 边表第 7 条边的锚点写着 `4倍像素外推：30fps→7-8fps`，但正文 5 处正确描述了 binning-mode 下 AI-ISP 仍处理 4MP，帧率约 25-30fps。

**发现方式**：执行 R109 审计规则 4（"边表不得出现与更高级别证据矛盾的锚点"）时发现。

**矛盾分析**：
- 边表 L5 锚点："30fps→7-8fps"（无 binning 的线性外推假设）
- 正文 L1 证据："binning-mode 降至 4MP，AI-ISP 增量 0MB"（§2.1.1）
- 正文 L3+L5 证据："帧率约 25-30fps"（§6.2）

**修正动作**：将边表锚点改为 `binning-mode下处理4MP，AI-ISP帧率约25-30fps（与4MP@30fps实测相当，需实测确认PPVD/NS/CDS并发衰减）`

---

## 案例5：发前自检表残留旧值（P5）

**错误**：C1/C2 修正后，附录B 发前自检表中仍写着 `Media峰值余量-6.02MB（超出）`，未随修正更新。

**发现方式**：执行 `grep -6.02` 全报告，发现附录B一处残留。

**修正动作**：
1. 将附录B旧值 `-6.02MB` 修正为 `-14.18MB`
2. 补充 `DDR3 2+1推荐方案余量113.82MB（44.5%）充裕`
3. 再次 grep 确认 0 残留

## 从本案例提炼的核心教训

1. **DDR容量是最高频错误点** → 每条结论落笔前强制查表
2. **加权增长因子不能心算** → 必须展开到每一项
3. **数字修改 = grep旧值全覆盖** → 不可假设已全部更新
4. **R109边表与正文是双向约束** → 边表锚点必须能在正文中找到完全一致的数字
5. **binning-mode等关键机制必须在边表中占据L1位置** → 防止低级别遍历其假设
