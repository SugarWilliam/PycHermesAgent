
## functional-logic-reviewer Skill 功能概览

**functional-logic-reviewer** 是一个面向嵌入式 Linux 代码变更的**功能与逻辑评审** skill，用于在代码审查中系统化地发现缺陷。

### 核心定位

- 做**功能与逻辑验证**，而不是只做结构/风格检查
- 结合**假设驱动**、**调用链追踪**、**7 维验证**和嵌入式领域知识
- 适用于 IPC、网络、音频、视频、存储、系统等嵌入式 Linux 模块的 SVN/Git diff 评审

### 两种评审模式

| 模式 | 触发条件 | 思路 |
|------|----------|------|
| **Diff-Driven（默认）** | 只有 diff/changelog | 从代码推断意图 → 形成缺陷假设 → 逐一验证 |
| **Requirement-Driven** | 有需求文档（可配合 diff） | 按需求逐条验证 → 按场景追踪调用链 |

Requirement-Driven 模式能发现**遗漏缺陷**（需求有但代码未实现），而 Diff-Driven 只能检查已有代码中的问题。

### 评审流程（Diff-Driven）

1. **Phase 0：分级与优先级**
   按风险对变更分类（并发/锁/ISR、状态机、IPC 等为高优先级）。

2. **Phase 1：假设形成**
   根据变更类型预先列出可能的缺陷假设（如锁改动 → 死锁、优先级反转等），再对照代码验证。

3. **Phase 2：深度分析**
   - 提取变更的文件、函数、参数
   - 阅读完整函数及调用上下文
   - **强制调用链追踪**：向上到入口、向下到 IO/IPC 等、横向到跨模块数据流
   - **7 维验证**：功能、状态机、边界、时序、配置、异常、影响

4. **Phase 3：嵌入式 Linux 专项检查**
   针对内核/驱动、用户态应用做领域检查（DMA、锁、IPC、定时器、资源、信号、串口、看门狗、RT 调度等）。

5. **Phase 3b：命名与拼写**
   检查 Linux 风格命名、拼写和缩写规范。

6. **Phase 4：跨版本关联**
   检查多版本间的冲突、不完整修复链、分散变更、回归引入等。

7. **Phase 5：问题分类**
   按置信度（Confirmed / Likely / Suspicious / FYI）和严重程度（Blocker / High / Medium / Low）分类。

8. **Phase 6：报告生成**
   生成 `review_report.md`，包含调用链、7 维结论、问题列表、回归测试建议等。

### 适用场景

- 评审 SVN/Git diff（嵌入式 Linux 项目）
- 做比结构审查更深的功能验证
- 审计涉及状态机、并发、IPC、定时器、DMA、ISR、电源管理的变更
- 版本发布前的架构审计
- 结合需求文档做需求驱动的深度评审

### 触发关键词

`code review`、`functional review`、`logic verification`、`call-chain analysis`、`impact analysis`、`审查`、`评审`、`逻辑验证` 等。
