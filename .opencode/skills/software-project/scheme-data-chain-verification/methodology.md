# 方法论详解：锚点定义、加权增长因子、编码能力量化

## §0 事实 SSOT 与命名约定

1. **芯片标称、DDR 硬件规格、产品矩阵与手册条文** 以**当前项目已采纳**的 datasheet、BOM/物料承认及 `reolink_agent` 知识库/正式手册为准。下文算式、示例与表格中的**标称/案例数**仅用于**演算结构说明**，定稿前须替换为**可追溯出处**的数值，不得将本文件中的教示性数字直接作为对外承诺依据。

2. 本技能包内为叙述方便使用的 **本技能内叙事标签**（如质量分模型、残差/量纲检测、边表闭包、MECE 基线、SS 级路径等）**不是**独立可安装的外部工程工具、代码仓库名或需单独调用的程序；均指本 `scheme-data-chain-verification` 包内已定义的分析步骤与检查表。

## §1 数据锚点定义与分类

### 1.1 什么是锚点

锚点是方案论证报告中**可独立验证的事实陈述**，具备以下属性：
- 已有出处（实测/官方规格/手册/用户输入）
- 可被其他结论引用为推理前提
- 在 R109 边表中作为一个节点存在

### 1.2 锚点证据等级与数据源可靠性

| 等级 | 定义 | 可靠性Q | 示例 |
|:----:|------|:------:|------|
| **L1** | 官方数据/手册/规范 | 1.00 | 芯片datasheet编码性能：10M@30fps |
| **L2** | 经过验证的公共知识 | 0.95 | Gbit→MB换算：1Gb=128MB |
| **L3** | 可直接计算的确定性推导 | 0.90 | 15.7MP×20fps=315MP/s |
| **L4** | 工程经验/领域共识 | 0.70 | "DDR4单价通常比DDR3高20-30%" |
| **L5** | 基于实测的外推/推断，需实测验证 | 0.60 | 12MP实测峰值余量→16MP推算余量 |
| **L5+** | 多路径独立推算收敛验证 | 0.85 | 三法（组件增量/简单BW/加权因子）均指向同一结论 |

> **可靠性Q** 本技能**质量分模型**（教示性记法）：`Q = w_c×completeness + w_a×accuracy + w_t×timeliness`。L5+ 为多路径交叉验证加分。当关键数字的 Q < 0.70 时必须标注 `[待实测验证]` 并列入风险表。命名约定见 §0。

### 1.3 关键数字锚点提取表模板

对每个方案论证报告，构建如下表：


### 1.4 范畴错误量纲速查

> **关联**：本技能**残差/量纲**叙事；量纲混淆是重算冲突的常见根因（与 §1.5 2σ 检测配合）。命名约定见 §0。

| 易混淆对 | 正确关系 | 常见错误 | 检查方法 |
|---------|---------|---------|---------|
| **MB vs Mb** | 1MB = 8Mb, 1Gb = 128MB | 用 1024 而非 128 换算 | grep `Gb.*MB\|Mb.*MB` 交叉验证 |
| **带宽(MB/s) vs 容量(MB)** | 带宽=像素BW/编码压缩比；容量=帧存buffer | 用带宽值填容量位 | 检查单位后缀是否一致 |
| **MP/s vs MP** | MP/s = 分辨率(MP) × 帧率(fps) | 混用分辨率与像素带宽 | 确认上下文：编码能力用MP/s，内存规格用MP |
| **Gbit vs GB** | 1GB = 8Gbit | DDR总容量写 GB 但用 Gbit 值 | DDR命名用Gbit(1+1)，分配用MB(128) |
| **MHz vs Mbps** | DDR频率 vs 带宽 | 频率值直接用于带宽计算 | 确认公式：BW = 频率 × 位宽 × 2(DDR) ÷ 8 |

> **审计方法**：grep 报告全文，对每个数字检查其上下文单位是否与所在维度匹配。单位不匹配 → 标记 P1 范畴错误。

### 1.5 重算冲突检测：异常值 2σ 法

> **关联**：本技能**多路径重算/残差**叙事。当同一物理量在报告中被多路径推导且出现不一致时触发。命名约定见 §0。

**检测条件**：同一物理量（如 Media 峰值占用）在报告中出现 ≥2 个不同数值。

**算法**：
```
μ = 组内均值
σ = 组内标准差

对每个数值 xᵢ：
  残差 = |xᵢ - μ|
  if   残差 > 3σ → P0（致命冲突，必须解决才能定稿）
  elif 残差 > 2σ → P1（显著冲突，需显式声明采纳值并说明排除理由）
  elif 残差 > 1σ → P2（轻微差异，建议标注收敛路径）
```

**示例**（三法校准案例）：
```
组: [139.21, 129.36, 142.18]
μ = 136.92, σ ≈ 5.45

139.21: 残差 = 2.29 → < 1σ → P2（轻微）
129.36: 残差 = 7.56 → > 1σ, < 2σ → P2（轻微）
142.18: 残差 = 5.26 → < 1σ → P2（轻微）

结论：三法数值不同但无 >2σ 异常，定性收敛。保守取 142.18MB。
```

> **处理规则**：P0 冲突必须修正。P1 冲突须在报告中显式写出采纳值和排除理由。P2 差异建议写出收敛路径（如在 §5.1 添加三法比较表）。

## §2 内存容量推算：加权增长因子方法

### 2.1 方法思想

不是直接从绝对组件大小推算内存占用，而是：
1. 从**实测基准**（已知场景的实测峰值占用）出发
2. 按**组件分类**加权计算增长
3. 每个组件按其对分辨率/帧率的敏感度分配不同的增长因子

### 2.2 标准流程

**步骤1**：提取实测基准峰值占用

```
峰值占用 = 内存分配值 − 实测峰值余量
```

**步骤2**：计算分辨率增长因子

```
R_growth = 新分辨率 / 基准分辨率
```

例如：15.7MP / 11.3MP = 1.39

**步骤3**：计算帧率变化因子

```
F_growth = 新帧率 / 基准帧率
```

例如：20fps / 25fps = 0.80

**步骤4**：计算像素带宽增长因子

```
BW_growth = R_growth × F_growth
```

例如：1.39 × 0.80 = 1.11

**步骤5**：组件分类与增长因子分配

| 组件 | 占比 | 增长因子 | 说明 |
|------|:----:|:--------:|------|
| ISP前端管线frame buffer | 40% | 1.39 | 与分辨率线性相关 |
| AI-ISP管线buffer | 2% | **1.0** | binning-mode后处理4MP，不增长 |
| 编码器YUV buffer+StreamBuffer | 35% | 1.11 | 与像素带宽正相关 |
| 其他（共享内存等） | 23% | 1.11 | 与像素带宽正相关 |

**步骤6**：计算加权增长因子

```
加权增长因子 = Σ(组件占比_i × 增长因子_i)
```

**必须写出完整展开式**：
```
= 0.40×1.39 + 0.02×1.00 + 0.35×1.11 + 0.23×1.11
= 0.556  + 0.020  + 0.3885  + 0.2553
= 1.2198 → 1.22
```

**步骤7**：推算峰值占用

```
推算峰值占用 = 基准峰值占用 × 加权增长因子
```

**步骤8**：推算峰值余量（各配置）

```
DDR3 1+1 (128MB Media):  128 − 推算占用
DDR3 2+1 (256MB Media):  256 − 推算占用
DDR3 2+2 (256MB Media):  256 − 推算占用
DDR4 1GB  (512MB Media):  512 − 推算占用
```

### 2.3 关键约束

1. **AI-ISP组件增长因子恒为1.0**（binning-mode机制）
2. **加权增长因子必须展开到每一项**，禁止跳跃式心算
3. **OS内存独立推算**（使用1.10因子）
4. Media+OS分配之和 = 总容量（强制校验）

## §3 芯片编码能力量化评估

### 3.1 基本公式

```
像素带宽 (MP/s) = 分辨率 (MP) × 帧率 (fps)
超出比例 (%)    = (需求像素带宽 / 标称像素带宽 − 1) × 100
```

### 3.2 标称像素带宽换算

```
标称像素带宽 = 标称分辨率 × 标称帧率
```

| 芯片 | 标称规格 | 标称像素带宽 |
|------|---------|:-----------:|
| NT98538A | 10M@30fps | **300MP/s** |
| NT98539G | 13M@30fps | **390MP/s** |
| NT98539A | 16M@30fps | **480MP/s** |

### 3.3 可行性分级

| 超出标称 | 等级 | 动作 |
|:--------:|:----:|------|
| ≤0% | ✅ 可行 | 直接支持 |
| 0% ~ 10% | ⚠️ 边界 | **需实测验证编码稳定性** |
| 10% ~ 30% | ⚠️ 紧张 | 需FAE确认+实测 |
| >30% | ❌ 不可行 | 排除该芯片 |

### 3.4 双规格对比策略

对于同一个分辨率有两种帧率目标的场景：

```
目标1: 16MP@25fps = 393MP/s → 与标称比较
目标2: 16MP@20fps = 315MP/s → 与标称比较
结论: 以超出比例较小的为备选，较大的为排除依据
```

## §4 Binning-mode机制对推算的影响

### 4.1 机制描述

> 高像素(≥12MP)场景下，AI-ISP开启binning-mode，处理分辨率降低4倍（16MP→4MP），pipeline buffer大幅缩小。

### 4.2 对计算的影响

| 维度 | 无binning假设 | binning-mode实际 | 差异 |
|------|:------------:|:---------------:|:----:|
| AI-ISP处理分辨率 | 16MP | 4MP | 4x↓ |
| AI-ISP DDR带宽 | 随分辨率线性增长 | **基本不变** | 关键 |
| AI-ISP NPU算力 | 随分辨率线性增长 | **基于4MP** | 关键 |
| AI-ISP内存增量 | 与分辨率正相关 | **0MB** | 关键 |

### 4.3 常见错误

> **错误**：按4倍像素外推计算AI-ISP帧率，得出30fps→7-8fps。  
> **正确**：binning-mode下AI-ISP仍处理4MP，帧率应接近4MP@30fps实测（~25-30fps）。

## §5 单元换算速查

| 换算 | 公式 |
|------|------|
| Gbit → MB | ÷8（1Gbit = 128MB） |
| Gbit → GB | ÷8（1Gbit = 0.125GB） |
| MP → 像素 | ×1,000,000 |
| MP/s → 像素/s | ×1,000,000 |
| MB/s → Gbps | ×8÷1000 |
