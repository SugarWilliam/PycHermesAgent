# R109边表构建规范与审计规则

## §1 边表结构

每条边由 6 个字段组成：

```
| 源 | 目标 | 边类型 | 证据等级 | 前置条件状态 | 锚点 |
```

### 字段定义

| 字段 | 说明 | 取值 |
|------|------|------|
| **源** | 已知事实/数据 | 锚点ID或具体数值 |
| **目标** | 从源推导出的结论 | 具体陈述 |
| **边类型** | 推理方式 | `计算/满足` `因果/推导` `实现/满足` `外推/推断` `外推/机制` |
| **证据等级** | 数据可靠度 | L1(官方) L2(公共知识) L3(确定性推导) L4(经验共识) L5(外推需验证) |
| **前置条件状态** | 源是否已验证 | ✓已验证 / ✗未验证 |
| **锚点** | 可验证的具体数值 | 数字或引用 |

---

## §2 链式识别

从边表中提取因果链，每条链由连续的多条边组成：

```
链式模型: A → B → C → D
(源→目标) 边1 + (目标成为源→新目标) 边2 + ...
```

### 标准链式分类

| 链路名 | 边序列 | 含义 |
|--------|--------|------|
| **产品→编码** | 分辨率→像素带宽→与标称比较 | 判断芯片编码是否达标 |
| **芯片→AI算力** | NPU总算力→AI-ISP占用→余量评估 | 判断AI并发是否可行 |
| **实测→推算→DDR** | 实测基准→推算峰值→多配置对比 | 判断DDR配置是否充足 |
| **机制→优化** | Binning-mode→处理分辨率→带宽需求 | 评估关键优化机制效果 |

## §3 审计规则（P0 Blocking）

### 规则1：锚点-正文一致性

> R109边表中的每一个锚点，必须在正文中找到**数值完全相同**的表述。

**审计方法**：
1. 提取边表中所有锚点值
2. grep 报告全文查找每个锚点值
3. 确认每个值在正文中出现且与边表一致

**违例示例**：
```
边表锚点: "4倍像素外推：30fps→7-8fps"         ← 边表
正文§6.2: "binning-mode下处理4MP，帧率约25-30fps"  ← 正文
→ 矛盾！边表锚点与正文binning-mode机制冲突。
```

### 规则2：L5边的前置条件

> 所有 L5（外推/推断）边的前置条件状态**必须为 ✗**。

原因：L5意味着该推断未经实测验证，前置条件不满足。

### 规则3：证据等级不向下污染

> 低等级边（L5）的结论**不得**作为高等级边（L1/L2）的源。

即：推断不能作为"官方事实"的前提。

### 规则4：边表不得包含已被正文淘汰的锚点

> 若报告已在正文中采用新的正确值，边表锚点必须同步更新，**不得保留旧值**。

**常见违例**：C1/C2修正后，边表锚点未同步更新。

### 规则5：闭包完整性（P1 Blocking）

> **来源**：本技能 **边表闭包**要求。每个「输出结论」节点必须能沿边反向追溯到锚点输入集，不可出现断裂。命名约定见 [methodology.md](methodology.md) · §0。

即：报告的任一关键结论数字，其推导所需的所有输入参数均须在报告中有定义，且每个中间推算值可继续追溯直至 L1/L2 锚点。

**审计方法**：
1. 从边表的每个「目标」节点出发
2. 找到其对应的「源」节点
3. 若源节点是中间推算值（L3/L5），递归执行步骤 1-2
4. 若某源在报告中无定义 → **悬空前提出**
5. 若某目标（关键结论）无法追溯到 L1/L2 锚点 → **闭包不完整**

**违例级别**：
- 悬空前提且关键结论依赖 → **P0**
- 悬空前提但非关键结论 → **P1**
- 闭包不完整（缺部分中间推导链） → **P1**

### 规则6：无悬空/无孤儿（P1 Blocking）

> **来源**：本技能 **MECE/覆盖**要求。报告中每个关键数字必须出现在至少一条 R109 边中（作为源或目标）。边表中的每个节点必须在正文中有对应表述。命名约定见 [methodology.md](methodology.md) · §0。

**两类违例**：

| 违例类型 | 定义 | 示例 | 级别 |
|---------|------|------|:--:|
| **悬空前提** | 边引用了一个在报告中无定义的数字 | 边表写「基准占用 116.54MB」但正文未给出该值由来 | P1 |
| **孤儿结论** | 关键数字在正文中出现但在边表中无对应边 | 报告 §5 写「编码余量 28.8MP/s」但边表无该值的任何边 | P1 |
| **链式断裂** | 边序列 A→B→C 中 B 缺失 | A→C 直接跳跃，缺少中间 B 的定义和推导 | P0 |

**审计方法**：
1. 列出报告正文中所有关键数字
2. 列出边表中所有源/目标/锚点
3. 正文数字 ∉ 边表节点 → 孤儿结论
4. 边表源节点 ∉ 正文 → 悬空前提
5. 边序列中存在跳跃（A 直接到 C 无 B） → 链式断裂

## §4 审计流程

```
1. 提取报告中所有关键数字 → 建立锚点ID表
2. 从边表中提取每条边的源/目标/锚点
3. 对每条边执行规则1-6检查（R1锚点一致、R2 L5前置、R3不向下污染、R4无淘汰、R5闭包完整、R6无悬空/孤儿）
4. 记录所有违例，标注P0/P1级别
5. 修正违例后重新执行步骤1-4
```

---

## §5 边覆盖度评估

```
边覆盖率 = 已验证的边数 / 报告推理链路所需的最小边数
```

- 100%：所有推理链路可溯源，无缺口
- <100%：存在不可溯源的数字或结论
